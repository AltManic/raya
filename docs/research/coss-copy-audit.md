# coss copy-source audit — MIT/AGPL boundary, theme provenance, attribution

Resolves [#22](https://github.com/AltManic/raya/issues/22). Research only — not legal advice.

**Pinned source:** [`github.com/cosscom/coss`](https://github.com/cosscom/coss) at
`e937becd2d5ffb5c621eed6f8b1f223cbb6051e7` (2026-09-08, "feat: migrate TanStack Table to v9 (#848)").
Citations below use the shorthand `coss@e937bec:<path>` for that commit.

**Bottom line:** copy coss's MIT registry tree (`apps/ui/registry/default/**`) and its MIT
theme publications. Never copy from `packages/ui/**` (AGPL), including the canonical
`packages/ui/src/styles/globals.css`. The docs-site chrome in `apps/ui/components/**` is
partly MIT and partly a thin wrapper over AGPL `@coss/ui/*`; most of it cannot be copied
verbatim. The MIT registry republishes nearly the whole theme — colors, chart/code tokens,
fonts and the toast/otp-field/skeleton keyframes — across `registry-styles.ts`,
`registry-ui.ts` and `public/r/*.json`. The only token content without an `apps/ui` MIT
publication is the derived radius scale (identical formulas are published in MIT
`apps/origin/app/globals.css`) and a toast `prefers-reduced-motion` guard; see section 3.

## 1. The license boundary, from primary evidence

coss's own boundary statement (`coss@e937bec:LICENSING.md`):

> This repository uses a mixed licensing approach. The default license for this project is
> [AGPLv3.0](LICENSE).
>
> ## MIT
>
> The following directory and their subdirectories are licensed under their original
>
> ```
> apps/origin/
> apps/ui/
> ```

Note the sentence is literally truncated in the repo (it ends at "under their original");
there is no accompanying MIT text in `apps/ui/`. Supporting declarations:

| Path | Declaration/citation |
| --- | --- |
| `LICENSING.md` | `apps/origin/`, `apps/ui/` are MIT; everything else defaults to AGPLv3 |
| `apps/ui/package.json` | `"license": "MIT"` |
| `apps/ui/README.md:73-75` | "This project is licensed under the MIT License. See the [LICENSE](../../LICENSING.md) file for details." |
| `apps/origin/package.json`, `apps/origin/LICENSE.md` | MIT; the only MIT **license text + copyright notice** anywhere in the pinned tree |
| `packages/ui/package.json` | `"license": "AGPL-3.0-or-later"` — so every file under it, including `src/styles/globals.css`, `src/components/**`, `src/shared/**`, `src/fonts/**` |
| `package.json` (root) | `"license": "AGPL-3.0-or-later"` (monorepo default) |
| `LICENSE` (root) | GNU AGPLv3 text |

The only copyright line coss ships is in `coss@e937bec:apps/origin/LICENSE.md`:
"Copyright (c) 2025 coss.com / Originally Copyright (c) 2025 Origin UI". `apps/ui/` itself
ships **no** LICENSE file and no per-file copyright headers (`git grep -inE "copyright|SPDX"`
over `apps/ui` and `packages/ui` returns nothing). See section 6 for how to phrase attribution.

Directory-based licensing is what coss declares, so **the directory a file lives in decides
its license** — not where the content was authored. That distinction matters, because the
MIT and AGPL trees are near-duplicates of each other (section 2).

## 2. The MIT registry is upstream; the AGPL package is a synced mirror

`apps/ui/scripts/sync-ui.mts` copies **registry → package**, not the other way round
(`coss@e937bec:apps/ui/scripts/sync-ui.mts:6-20,81-101`):

```
sourceRoot = apps/ui/registry/default            (MIT)
targetRoot = packages/ui/src                     (AGPL)
ui       → components/     hooks → hooks/     lib → lib/     base-ui → base-ui/
rewrite: "@/registry/default/ui/*" → "@coss/ui/components/*"
         "@/registry/default/lib/*" → "@coss/ui/lib/*", etc.
```

Diffing all 62 registry files against their `packages/ui` counterparts, every difference is
an import-path rewrite plus import re-ordering; no logic differs (checked for
`ui/*.tsx` ×54, `hooks/*.ts` ×2, `lib/*.ts` ×2, `base-ui/*.ts` ×4). Example
`coss@e937bec:apps/ui/registry/default/ui/button.tsx:7-8` vs
`coss@e937bec:packages/ui/src/components/button.tsx:5-6`.

The MIT registry tree:

| Kind | Files | Path |
| --- | --- | --- |
| UI primitives | 54 | `apps/ui/registry/default/ui/*.tsx` |
| Particles (examples) | 508 | `apps/ui/registry/default/particles/*.tsx` |
| Hooks | 2 (`use-copy-to-clipboard`, `use-media-query`) | `apps/ui/registry/default/hooks/*.ts` |
| Lib | 2 (`utils`, `segmented-control`) | `apps/ui/registry/default/lib/*.ts` |
| Base UI re-exports | 4 | `apps/ui/registry/default/base-ui/*.ts` |

The shadcn CLI consumes *generated* JSON from the same directory: 579 files under
`apps/ui/public/r/` (577 registry items: 56 `registry:ui`, 508 `registry:block`,
2 `registry:style`, 3 `registry:font`, 6 `registry:lib`, 2 `registry:hook`, plus
`registry.json` and one stale generated file `p-input-group-25.json` that has no matching
item in `registry.json`) built by
`apps/ui/scripts/build-registry.mts` ("autogenerated", `coss@e937bec:apps/ui/scripts/build-registry.mts:1-40`).
Each component JSON embeds the full source with `@/registry/default/...` imports
(`coss@e937bec:apps/ui/public/r/button.json:files[0].content`), and items that need extra
CSS carry it too (`public/r/toast.json` `css` + `cssVars.theme`), so CLI installs are MIT
and self-contained.

**Rule for raya: copy from `apps/ui/registry/default/**` (or the `public/r/*.json` payloads).
Never copy `packages/ui/src/**`, even though it is byte-near-identical.**

Registry components are also framework-portable except the particles: no `apps/ui/registry/default/ui/*`
file imports `next`; 16 particles import `next/link`
(`git grep 'from "next' apps/ui/registry/default/particles`), which must become TanStack
Router links in raya.

### 2.1 `apps/origin` — the other MIT tree

`apps/origin/` is the second MIT directory (`LICENSING.md`; `"license": "MIT"` at
`coss@e937bec:apps/origin/package.json:57`, name `origin`). It is a **legacy, pre-acquisition
Origin UI snapshot, Radix-based** ("Legacy snapshot … support and maintenance are limited" —
`coss@e937bec:apps/origin/README.md:1-5`). Contents: 1469 files — its own Next.js gallery
app (`app/`, `components/`) and an old shadcn-style registry tree
`apps/origin/registry/default/{ui,components,hooks,lib}` (43 `ui` files).

It is **not the adoption target**: its components use Radix/react-aria primitives
(`apps/origin/package.json` deps: `radix-ui`, `react-aria`, `react-day-picker`, …), while
raya is adopting the Base UI registry in `apps/ui`. Mixing the two would drag a second
primitive stack and a different API into raya.

Its value for this audit is one file: `apps/origin/app/globals.css` (152 lines, MIT) is a
**complete token implementation** of the older Origin look — it publishes the derived radius
scale `--radius-sm/md/lg/xl` (`coss@e937bec:apps/origin/app/globals.css:41-44`), chart tokens
(`:68-72`, `:103-107`, whose oklch values match coss ui's chart palette), and `@layer base`
with the `body` rule (`:118-123`). Its *core* color values, however, are the old zinc-based
oklch palette (`--background: oklch(1 0 0)`, `--secondary: …zinc-100`), not coss ui's
neutral + `color-mix`/`--alpha` system — so do not take the look from here. Use it only as an
MIT witness for the radius formulas and chart colors if `apps/ui` values are ever unclear.

Do not copy `apps/origin` brand assets (`app/favicon.ico`, `app/opengraph-image.jpg`,
`app/twitter-image.jpg`) or its README prose. It ships no font binaries (no
`.woff/.woff2/.ttf/.otf` in the tree).

### 3.3 Diff verdict: usable core, but not complete

Diffing `styling.mdx`'s CSS block against `packages/ui/src/styles/globals.css` (both at
`e937bec`) yields:

**Present in the MIT block:** `@theme inline` color/font mappings (except chart/code),
skeleton animation + keyframes, full light/dark core tokens (background, foreground,
card, popover, primary, secondary, muted, accent, destructive, info, success, warning,
border, input, ring, sidebar-*, `--radius`), fonts prose.

**Missing from `styling.mdx` but present in the AGPL file:**

| Missing | Notes |
| --- | --- |
| `@import "tailwindcss"`, `@source` directives | N/A — raya has its own Tailwind entry |
| `@custom-variant dark (&:is(.dark *))` | Raya's `registry/default/styles/core.css` already defines it |
| `@custom-variant fixed (&:is(.layout-fixed *))` | No `fixed:` usage in `registry/default/ui` — not needed by primitives |
| `--breakpoint-3xl: 1600px`, `--breakpoint-4xl: 2000px` | No `3xl:`/`4xl:` usage in `registry/default/ui` |
| `--color-chart-1..5`, `--color-code*` mappings + `--chart-1..5`, `--code*` values | **Values are published in `registry-styles.ts` / `public/r/style.json`** (light and dark), just not in the mdx block |
| `--radius-sm/md/lg/xl` theme scale | The mdx block and style item publish only `--radius: 0.625rem`; the derived formulas are **not** in `styling.mdx`, but the identical `calc()` scale is published in MIT `apps/origin/app/globals.css:41-44` (and raya's `core.css` already carries it) |
| `--tw-shadow-color: #000` | Minor shadow default; not published |
| `--animate-caret-blink` + keyframes | **Published in MIT** as the `otp-field` registry item (`registry-ui.ts:410-425`; `public/r/otp-field.json` `css` + `cssVars.theme`), just not in the mdx block. Unused by `registry/default/ui`; only relevant if copying the OTP particle |
| `--animate-toast-success/error-odd/even` + 4 keyframes | Used by the MIT `ui/toast.tsx` (`coss@e937bec:apps/ui/registry/default/ui/toast.tsx:57-59`). **Published in MIT** as the `toast` registry item: `registry-ui.ts:720-801`, `public/r/toast.json` `css` + `cssVars.theme` — values match AGPL `globals.css` |
| `@media (prefers-reduced-motion: reduce)` guard for the toast animations | **Only in AGPL `globals.css:150-158`** — present in no MIT file. If wanted, have raya write its own generic guard |
| `@layer base` (`* { border-border outline-ring/50 }`, monospace `code/kbd/samp/pre`) | Republished in `registry-styles.ts` `css` / `style.json` `css`, not in mdx |
| `@utility container`, `@layer components` (steps, rehype-pretty-code, highlighted-word) | Docs-site presentation only; not part of the component token system |

**Value divergence (MIT ≠ AGPL), not just omission:**

| Token | `styling.mdx` / registry (MIT) | `packages/ui/.../globals.css` (AGPL) |
| --- | --- | --- |
| `.dark --background` | `color-mix(… neutral-950 95% …)` | `96%` |
| `.dark --popover` | `color-mix(… background 98% …)` | `96%` |

The registry also adds a `body { @apply bg-background text-foreground }` rule that the
canonical file does not have (`registry-styles.ts` `css` block). In other words the MIT
republication is a **curated, slightly divergent derivative**, not a verbatim subset.

**Practical guidance for raya:**

1. Take token values from the MIT registry (`registry-styles.ts`, `public/r/style.json`,
   `colors-neutral.json`) **plus the per-component `css`/`cssVars.theme` for `toast`,
   `otp-field` and `skeleton`** (embedding those two keyframe sets in raya's `core.css` when
   the corresponding components are copied). That is exactly what the coss CLI ships to
   consumers.
2. The radius formulas are published in MIT at `apps/origin/app/globals.css:41-44` (identical
   to AGPL `globals.css`); raya's `registry/default/styles/core.css` already carries them. The
   only coss token content with no MIT publication is the toast `prefers-reduced-motion`
   guard — write a generic guard in raya rather than copying AGPL.
3. Do not diff raya's output against the AGPL `globals.css` expecting byte equality — the
   two dark values differ by design at this commit (table above).
4. `get-started.mdx` is prose + CLI instructions, its only CSS block aliases `--font-heading`
   (lines 109-113), and it leads back to `@coss/ui/fonts` / `@coss/ui/components/*` (AGPL
   package), so it is not a copy source for code.

## 6. Required MIT attribution and where it should live

MIT's condition is to include the copyright notice and permission notice in copies or
substantial portions. For material copied from `apps/ui/` at `e937bec`:

- coss provides the MIT *grant* only via `LICENSING.md` + `apps/ui/README.md` + the
  `package.json` field; there is no MIT license text under `apps/ui/`.
- The only copyright notices coss ships are in `apps/origin/LICENSE.md`:
  `Copyright (c) 2025 coss.com` and `Originally Copyright (c) 2025 Origin UI`.
- The apps/ui code is the Origin UI lineage (README: "coss.com/ui (formerly Origin UI)"),
  so preserving the Origin UI line is the conservative choice.

Proposed action for raya:

1. Add a repo-root **`NOTICE`** (raya currently has no `LICENSE` or `NOTICE`; `docs/` holds
   only `docs/agents/` plus this audit in `docs/research/`). Keep it next to a future raya
   `LICENSE` rather than buried in `docs/`, because vendored-code attribution is
   conventionally root-level.
2. Include: provenance statement (repo, MIT directory, pinned commit), both copyright lines,
   the full MIT permission text, and the list of copied paths.

the sparse worktree; its files were read as blobs via `git show` (blobs fetched on demand).
